# דיווח מכירות יומי ושיבוץ מוכרות – רשת קוסמטיקה

אפליקציה לטלפון ולמחשב, בעברית. יש בה שלושה חלקים:

1. **דיווח יומי.** כל יועצת פותחת משמרת ומקבלת יעד אישי. היא רושמת כל עסקה תוך כמה שניות: סכום, מספר פריטים, קטגוריה, סוג ההגדלה, הצטרפות למועדון, החזרה או מכירה משותפת. היא גם מסמנת כל פנייה ללקוחה. המערכת מציגה את שעת הסיפתוח, את הסל הממוצע (ATV), את מספר הפריטים לעסקה (UPT), את אחוז ההגדלה ואת ההמרה, הכול בזמן אמת.
2. **תמונת מצב לפי ההיררכיה.** הרמות הן יועצת ← אחראית משמרת ← מנהלת סניף ← מנהלת אזור ← הנהלה. מנהלת הסניף רואה לוח חי של הסניף מול היעד ומול הקצב הצפוי לכל שעה. היא גם מגדירה יעדים: חודשי, ואחריו יומי ואישי.
3. **ניתוח ושיבוץ.** המערכת בונה לכל מוכרת פרופיל שמנוכה ממנו האפקט של החנות, ומציעה שלושה סוגי המלצות:
   - **זיווג למשמרות**
   - **שיבוץ לחנות**
   - **חונכות בין סניפים**

   כל המלצה כוללת הסבר, וכל המלצה מחכה לאישור של מנהלת. שום שינוי לא קורה אוטומטית.

## הפעלה מהירה (מצב דמו)

```bash
cd sales-app
npm install
npm run dev        # http://localhost:5173
```

כשאין חיבור ל-Supabase, האפליקציה עולה במצב דמו:
- הנתונים: 2 אזורים, 6 סניפים, 72 מוכרות ו-90 ימים של עסקאות.
- הנתונים נוצרים מחדש בכל טעינה.
- רק השינויים שלך נשמרים, בדפדפן.
- במסך הכניסה בוחרים תפקיד.

## מה המודל עושה

**פרופיל מנוכה-חנות (`src/lib/profiles.ts`).**
כל מדד מחושב ביחס למה שמוכרת ממוצעת הייתה עושה באותו סניף, באותו יום בשבוע ובאותה שעה. הערך 1.00 הוא הממוצע. כך אפשר להשוות מוכרת מסניף חלש למוכרת מסניף חזק.

הפרופיל כולל את המדדים האלה:

| מדד | מה הוא בודק |
|---|---|
| מכירות | התפוקה הכללית |
| סיפתוח | השעתיים הראשונות של משמרת פתיחה, והזמן עד העסקה הראשונה |
| סל ממוצע | גובה העסקה |
| פריטים לעסקה | כמה פריטים יש בעסקה |
| הגדלה | כמה עסקאות כוללות הגדלה |
| המרה | כמה פניות הופכות לעסקה |
| קטגוריות | כוח בכל אחת מחמש הקטגוריות |
| חלקי היום | בוקר, צהריים וערב |
| יציבות | כמה הביצועים קבועים ממשמרת למשמרת |

המערכת לא מציעה המלצות למוכרת עם פחות מ-15 משמרות.

**כימיה בין צמדים.**
השיטה היא "עם ובלי": כמה צמד מוכר כשהן עובדות ביחד, לעומת מה שכל אחת מוכרת בלי השנייה.

**זיווג למשמרות (`src/lib/matching/pairing.ts`).**
- המשמרות מתחלקות בין כל הצוות לפי היקף המשרה (חלוקה הוגנת), כך שהמערכת מחליטה מי עובדת עם מי ומתי, ולא מי עובדת בכלל.
- בכל משמרת בוקר יש מישהי חזקה בסיפתוח.
- הצוות מכסה את הקטגוריות החזקות של הסניף, ויש עדיפות לצמדים עם כימיה.
- תמיד יש אחראית בכל משמרת, והזמינות נשמרת.
- הסידור מושווה לסידור אקראי של אותו צוות.

**שיבוץ לחנות (`src/lib/matching/storeAssign.ts`).**
- נבדקת ההתאמה של כל מוכרת לכל סניף: תמהיל הקטגוריות, שעות העומס וסוג הסל.
- הפתרון מתקבל באלגוריתם Hungarian, בלי לשנות את מספר המוכרות בכל סניף.
- מעבר מוצע רק כשהשיפור גבוה מ-8%.
- מקדמות מותג ומנהלות לא זזות.

**חונכות (`src/lib/matching/mentoring.ts`).**
- לכל מיומנות מצמידים חונכת מהרבעון העליון בסניף אחר לחניכה מהרבעון התחתון.
- מטפלים רק בפערים של 15% לפחות.
- כל חונכת מקבלת עד 2 חניכות.
- אחרי האישור המערכת מודדת את המיומנות 4 שבועות לפני החונכות ואחריה.

> **חשוב:** כל ה-₪ ש"המערכת צופה" מחושבים לפי המודל. כדאי לבדוק את ההמלצות בכמה סניפים לכמה שבועות, ולהשוות לסניפים בלי שינוי, לפני שמרחיבים לכל הרשת.

## חיבור לנתונים אמיתיים (Supabase)

1. פותחים פרויקט חינמי ב-[supabase.com](https://supabase.com).
2. בעורך ה-SQL מריצים את `supabase/migrations/001_schema.sql`. הקובץ יוצר את הטבלאות, את ההרשאות לפי תפקיד (RLS) ואת ה-Views לדוחות.
3. יוצרים אזור, סניף ומשתמשת הנהלה ראשונה:
   ```sql
   insert into regions (name) values ('מרכז') returning id;
   insert into stores (name, region_id) values ('סניף ראשון', '<region id>') returning id;
   insert into profiles (email, name, role) values ('you@example.com', 'שם', 'admin');
   ```
4. יוצרים את הקובץ `sales-app/.env.local`:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=...
   ```
5. נכנסים עם קוד חד-פעמי שנשלח למייל. את שאר העובדות מוסיפים ממסך **ניהול** עם כתובת המייל שלהן. החשבון מתחבר לפרופיל אוטומטית בכניסה הראשונה.

אפשרות לבדיקה עם נתוני דמו: `npm run seed:sql` יוצר את הקובץ `supabase/seed.sql`, ואותו מריצים אחרי הסכמה.

**הרשאות (RLS):**

| תפקיד | מה מותר |
|---|---|
| יועצת | רואה את הסניף שלה. מדווחת רק על עצמה, ומתקנת עסקאות רק באותו יום. |
| אחראית משמרת | מתקנת עסקאות בסניף. |
| מנהלת סניף | מגדירה יעדים. קוראת את נתוני האזור כדי לשבץ תגבור. |
| מנהלת אזור | רואה את האזור, מנהלת אנשים ומאשרת המלצות. |
| הנהלה | רואה ועושה הכול. |

## פריסה

```bash
npm run build      # התוצר בתיקייה sales-app/dist
```

אפשר להעלות ל-Vercel או ל-Netlify (תיקיית שורש: `sales-app`, פקודה: `npm run build`, פלט: `dist`). את משתני הסביבה של Supabase מגדירים בהגדרות הפרויקט שם.

## בדיקות

```bash
npm test           # Vitest
```

הבדיקות מכסות שני תחומים:
- **חישובי המדדים:** סל ממוצע (ATV), פריטים לעסקה (UPT), סיפתוח, פיצול 50/50, קיזוז החזרות, המרה וחלוקת יעדים.
- **אלגוריתמי השיבוץ:** הבדיקות רצות על נתוני הדמו, שבהם התשובה הנכונה ידועה מראש:
  - "נועה" (כוכבת בישום בסניף של טיפוח) ו"מיכל" (ההפך) מוחלפות ביניהן.
  - "שירן" ו"ליאור" (צמד עם כימיה) משובצות יחד.
  - "רותם" (חלשה בסיפתוח) מקבלת חונכת לסיפתוח מסניף אחר.

  הבדיקות גם מוודאות שהשיבוץ מכבד זמינות, מכסת משמרות, משמרת אחת ביום ואחראית בכל משמרת.
